# AppData 磁盘清理助手 v2.1.1

查看并清理 `C:\Users\<你>\AppData` 下越积越大的目录。纯 Python 实现，**运行无需联网、无需 Node**。核心逻辑仅用标准库；v2.1 起的桌面窗口壳额外使用 `pywebview`（依赖 Windows 自带的 WebView2 运行时，Win10/11 默认自带），无 WebView2 时自动退回浏览器模式。

> 版本路线：次版本依次递增、不跳号 —— 1.5 可观测性 / 1.6 CLI / 1.7 规则库导入导出 / 1.8「申请解锁」引导 / 1.9.0 多根目录 / 2.0.0 稳定收口版，六版均已发布 → **2.1.0 界面窗口化（已发布）**：默认桌面窗口不再开浏览器 → **2.1.1 工程化与验证收口（本版）**：pytest / 覆盖率门槛 / CI 门禁与接口容错。规则详见 `PLAN-1.5.md`；各版规划见 `PLAN-1.6.md` ～ `PLAN-2.1.md`。

| 项 | 要求 |

## 使用

两个启动入口，内容都是纯 ASCII，任何系统语言下都不会乱码：

| 文件 | 用途 |
|---|---|
| `启动工具.bat` | 普通权限，日常清理缓存够用 |
| `以管理员身份启动.bat` | 会弹 UAC，点「是」后以管理员运行。遇到「拒绝访问」时用这个 |

也可以打包成**单文件 exe**（无需安装 Python 的机器也能跑）：

```
build_exe.bat        （一键构建；构建依赖版本锁定在 requirements-build.txt）
```

产物 `dist\AppDataCleaner.exe` 双击即用；`config.json`/`logs`/`cache` 自动生成在 exe 旁边。exe 不内嵌 UAC 清单（避免每次启动弹窗），提权走界面里的「以管理员身份重启」。

**v2.1 起，双击直接弹桌面窗口（不再开浏览器）**：界面套在原生窗口里，关闭窗口即停止服务。若窗口启动失败（如老系统缺 WebView2 运行时）会自动退回浏览器模式；也可加 `--web` 参数强制走浏览器。服务启动后会**自动在后台预热扫描**，打开页面即有数据。

1. 点「开始扫描」——第二次扫描走**增量**，通常不到 1 秒（需要精确值点「强制全量重扫」）
2. 用顶部**搜索框**（支持 `*` 通配，`/` 聚焦、`Esc` 清空）和**筛选 chips** 缩小范围
3. 勾选要清理的项目（红色「系统/程序」项禁选，`↑↓` + `空格` 也能选）
4. 点「预览并清理」→ 逐项核对体积、级别与用途说明 → 选处理方式 → 勾选两项确认 → 执行
5. 「移动到指定文件夹」执行后可**一键撤销**；结果页/历史页都能撤
6. 想省事就用侧栏的**一键清理安全缓存**：清单由服务端从扫描树枚举，只含绿色「安全缓存」项，疑似/数据/系统目录绝不参与，执行前进回收站、可还原
7. 「重复文件」页签：按**内容 MD5 全等**找重复（0 误报），每组默认保留最新一份、其余进回收站；硬链接/云盘占位/系统保护目录自动跳过；哈希有 30s 预算，超时给部分结果并标注
8. 「设置」页签可改默认移动目标、端口、重复检测参数，并添加**自定义规则**（格式 `路径段/段 | 级别 | 说明`）——用户 protected 优先级最高，但 safe 永远改不动系统保护目录。规则可**导出/导入 JSON 规则包**（v1.7 新增）：导出直接下载文件；导入会**替换**当前全部自定义规则，非法条目逐条报告后丢弃
9. 系统/程序数据（protected）行有**「引导」按钮**（v1.8 新增）：解释该目录为何被保护，给出 Windows 权限调整的官方推荐步骤并一键打开微软官方说明页；清理预览中的被拦截项也有「查看解锁引导」入口。本工具只提供说明与链接，**不代为修改任何权限、不执行任何解锁命令**
10. 扫描目录输入框旁有**「管理」**（v1.9 新增）：登记最多 8 个常用根目录（下载目录、开发缓存等），下拉一键切换。根目录必须位于当前用户目录内，内置默认根 `AppData` 不可删除；**登记只是快捷方式，不放宽任何扫描与删除安全校验**
11. 普通权限遇到「拒绝访问」不用重启：顶部横幅点**「以管理员身份重启」**，UAC 点「是」后服务自动以管理员重启、页面自动恢复
12. 「历史」页签顶部有**近 30 天清理趋势图**（每天释放空间折线，峰值自动标注）；「大文件」页签可切**「按扩展名聚合」**视图，勾一个类型即选中该类型下全部可清理文件，走同一确认流执行
13. 想彻底不管就用设置页的**定时自动清理**（v1.4 新增）：默认关闭，可选每天/每周与执行时刻；开启前先点「预览将清理的内容」，状态行会披露下次计划、上次执行与释放量、失败项与失败原因（v1.5 起）与跳过原因。只清绿色「安全缓存」，与一键清理是同一份服务端清单
14. 想知道「这几天什么在偷偷涨」就看**「变化」页签**：与上次扫描对比，列出新增目录、已移除、增长 Top20、缩小 Top20 和净变化。对比的是两棵扫描结果树、不额外读盘；本次若为增量扫描会提示增长/缩小可能低估，点「强制全量重扫」取精确值。第一次扫描没有对比基准，再扫一次即可
15. **「扩展名」页签**按全树文件类型汇总占用、文件数与占比条，点一行展开该类型主要藏在哪些目录。统计覆盖本次扫描读到的**全部文件**（不只是大文件），**本页只读**；要按类型清理请回「大文件 → 按扩展名聚合」，走同一套预览确认流
16. AppData 总量超过**空间预警阈值**（设置页，默认 10 GB、填 0 关闭）时，结果页顶部出横幅并给出超出量与两个入口（一键清理安全缓存 / 去查重复文件）。**只是提醒，不会自动删除任何东西**

## 命令行模式（v1.6 新增）

不带任何参数运行 = **桌面窗口版**（v2.1 起）；`--web` = 浏览器版；带动作参数才进入 CLI（**不启服务、不开界面、不占端口**）：

```bash
python server.py --scan --fresh                 # 只扫描，输出摘要，不删除
python server.py --dry-run --fresh             # 列出将清理的安全缓存项，不删除
python server.py --oneclick --yes --fresh     # 执行一键清理（默认移入回收站）
AppDataCleaner.exe --scan --json              # exe 同样支持，单行 JSON 供脚本解析
```

| 参数 | 说明 |
|---|---|
| `--scan` / `--dry-run` / `--oneclick` | 三选一、互斥；都不给 = 桌面窗口版（`--web` 换浏览器版） |
| `--yes` | **唯一能触发删除的开关**；`--oneclick` 不给它就只预览并以退出码 `4` 结束 |
| `--root` | 扫描根目录，必须位于当前用户目录内（越界直接拒绝，退出码 `3`） |
| `--max-depth` / `--fresh` / `--hot-mb` / `--big-mb` | 扫描参数，缺省同网页版 |
| `--json` | 单行 JSON；统一外层字段 `version / action / root / ok / exitCode / error` |
| `--version` / `-h` | 版本 / 帮助 |

退出码：`0` 成功、`1` 执行失败、`2` 参数或目录错误、`3` 越界拒绝、`4` 缺 `--yes` 未确认。清理走的是**网页版同一份服务端清单**（仅绿色「安全缓存」），默认移入回收站、写 `cli-oneclick` 历史，可从回收站还原；**不提供**永久删除、配置写入、无人值守 `--auto`、多根目录。

> ⚠️ `--yes` 只对本次显式调用生效。把 `--oneclick --yes` 写进计划任务或开机脚本，等于让它无人值守地执行删除 —— 请先用 `--dry-run` 核对清单，并自行承担调度责任。

## 常用扫描根目录（v1.9 新增）

扫描目录输入框旁的**「管理」**按钮用于登记常用根目录，避免每次手敲长路径。

| 步骤 | 操作 |
|---|---|
| 1 | 点「管理」→ 填「路径」，可选填「名称」→ 点「添加」 |
| 2 | 回到扫描区，点输入框的下拉箭头选一项，路径自动填入 |
| 3 | 列表右侧「删除」移除自定义项；内置默认根 `AppData` 恒排第一且不可删除 |

**约束与边界**

- 最多 **8 个**自定义根；路径须为绝对路径且**落在当前用户目录内**；盘符根、UNC、`..`、系统保护目录段（`Windows` / `Program Files` / `ProgramData` / `System32` / `$Recycle.bin` 等）一律拒绝；拒绝重复与相互嵌套；名称限 32 字。
- **登记只是快捷方式，不放宽任何安全校验**：`/api/scan` 的信任边界、越界拒绝、四级分类与删除确认流全部照旧。**未登记的路径照样能直接扫**，CLI 与旧客户端不受影响。
- 一次只扫**一个**根，不做多根并行；定时自动清理仍按「当前扫描结果」单点，不按根分策略。
- **跨盘根（如 `D://Downloads`）暂不支持**，与既有 `/api/scan` 边界一致；放宽需重新论证系统目录防护，属 2.1+ 候选。
- 旧 `config.json` 没有 `roots` 字段也能正常启动（自动补空表）；目录临时不可用时该条被降级丢弃并给出警告，不会卡住整个设置页。

## 四级分类

| 级别 | 含义 | 可否删除 |
|---|---|---|
| 安全缓存（绿） | 命中已知规则：系统临时文件、着色器缓存、崩溃转储、包管理器缓存。删了由程序重建 | 可删 |
| 疑似缓存（黄） | 名字像缓存但不在已知清单内，或厂商根目录（如 `Local\NVIDIA`） | 可删，但请先看说明 |
| 用户数据（蓝） | 程序配置、聊天记录、模型文件等 | 可删，风险自负 |
| 系统/程序（红） | `Local\Microsoft`、`Local\Programs`、`Local\Packages` 等 | **禁止删除**，仅可查看 |

鼠标悬停在级别标签上，会显示该目录「删了会怎样」。

## 安全设计

| 机制 | 说明 |
|---|---|
| 默认回收站 | 删除走系统回收站（可还原），永久删除需额外输入「永久删除」四字 |
| 段级保护规则 | 按路径段精确匹配，`Local\Microsoft` 拦截，但 `Local\MicrosoftEdge` 不会被误伤 |
| 二次确认令牌 | 预览生成一次性令牌（`secrets` 生成，10 分钟有效），执行时校验清单未被中途修改，用后即废 |
| 小批量逐项校验 | 每批最多 10 项，逐项校验是否真的删除成功 |
| 越界拒绝 | 只允许操作扫描根目录内部的路径，`C:\Windows` 等直接拒绝 |
| 目标目录校验 | 移动目标不能是系统目录、盘符根，也不能在被扫描目录内部 |
| 请求来源校验 | 校验 `Origin`/`Referer` 与 `Host`，挡住跨站请求 |
| 撤销清单校验 | manifestId 只接受严格格式，杜绝 `../` 穿越；逐项独立成败 |
| 操作日志 | `logs/clean-YYYYMMDD.log`（人类可读）+ `logs/clean-YYYYMMDD.jsonl`（历史页数据源） |
| 定时自动清理四条红线 | 默认关闭 · 只清 `safe` 级 · 扫描结果超 7 天跳过本轮 · 只进回收站且写历史（`auto-oneclick`）；与一键清理共用同一份服务端枚举清单，自动清理不可能清得更多 |

## 增量扫描的边界（重要）

增量只复用**最深一层**且「目录 mtime 未变、近 10 分钟无任何写入」的子树；上层目录每次都实际枚举，所以**目录结构永远准确**。唯一已知的近似场景：文件在目录内被**原地改写**（大小变化但目录 mtime 不变），此时体积沿用旧值。界面上出现蓝色「增量扫描」提示条时即为该状态，点「强制全量重扫」可取精确值。

另外 Windows 的目录枚举缓存可能让「刚新增的文件」在极短时间内不体现在父目录枚举出的 mtime 上，工具已在最深一层用直接路径复核一次 mtime；若仍怀疑数值不准，用「强制全量重扫」兜底。

**「变化」与「扩展名」两个分析页同样受增量影响**：复用子树沿用上次统计并标「可能低估」。若旧快照里还没有扩展名数据（刚升级到 1.4 时），首轮增量只统计到实扫文件、低估会更明显，页面会用更醒目的提示要求点一次「强制全量重扫」；全量扫描的聚合总量与文件数则与扫描树严格相等。

## 测试

```bash
python run_tests.py
```

会自动拉起服务并依次跑**全部分组**（脚本自带临时服务，跑完自动回收；`APP_NO_AUTOCLEAN=1` 关闭常驻调度线程）。分组职责如下，**具体断言数随版本演进，以脚本实际输出为准**：

- `tests/test_rules.py` —— 规则层（含 1.0 两处误判的回归用例）
- `tests/test_rulepkg.py` —— 规则包导入/导出（包校验矩阵、G1 提权专项、导入替换与持久化、坏包拒绝、往返一致）
- `tests/test_config.py` —— 配置校验（非法规则硬拒绝、启动容错、自定义规则优先级）
- `tests/test_api.py` —— 接口与安全（跨站、越界、令牌重放、目标目录、截断字段、版本贯通）
- `tests/test_contract.py` —— 接口契约（非 JSON、非对象 body、类型非法：不断连、返回 JSON、错误可读）
- `tests/test_flow.py` —— 端到端（扫描 → 回收站 → 移动 → 撤销 → 永久删除 → 只读文件 → 保护目录）
- `tests/test_increment.py` —— 增量（冷目录复用、深层新增检出、快照落盘、fresh 强制全量）
- `tests/test_m3.py` —— 历史与撤销（manifest、路径穿越拒绝、undo 回滚、清空回收站守门）
- `tests/test_m1.py` —— 配置接口与一键清理
- `tests/test_auto.py` —— 定时自动清理（守门矩阵、非法配置回退、仅 safe 闭环、幂等、历史披露、调度异常可见）
- `tests/test_dup.py` —— 重复文件检测（0 误报陷阱、硬链接/占位跳过、partial 预算）
- `tests/test_parallel.py` —— 并行扫描一致性（1/4/8 worker 与串行全等、worker 回退、diff 基准存活）
- `tests/test_diff.py` —— 目录变化对比（四类变化、根差口径、路径规范化、API 闭环含删除后「已移除」）
- `tests/test_warn.py` —— 空间预警阈值（校验边界、坏值回退、旧配置补默认值、接口贯通与 400 拒绝）
- `tests/test_ext.py` —— 全树扩展名聚合（聚合口径、Top 裁剪与披露、后缀归一、深层归属、增量沿用与 `partial`、旧格式快照兼容）
- `tests/test_gate.py` —— **安全门禁矩阵 G1–G6** + 配置向前兼容（G1 仅 safe / G2 7 天新鲜度 / G3 默认关闭 / G4 全部可撤销 / G5 CLI 无第二套删除路径 / G6 缺 `--yes` 零调用）
- `tests/test_cli.py` —— 命令行模式（入口分发、参数互斥、退出码、JSON 字段、越界、dry-run 与无 `--yes` 文件系统零变化、真删与历史、幂等）
- `tests/test_guide.py` —— 解锁引导（只读端点、链接白名单、零执行面静态断言）
- `tests/test_roots.py` —— 多根目录（校验矩阵、端点闭环、旧配置兼容、未登记根仍可扫）
- `tests/test_release_gate.py` —— 发版门禁可靠性（骨架破坏必被拦下、检查器纯函数、AST 零删除面、防递归约束）

退出码 0 表示全绿。测试会重建 `testdata/`，跑完即可删。

## 发版门禁（v2.0 新增）

`release_gate.py` 是**发版期唯一前置入口**：不进 exe、不改运行时行为、纯标准库。发版前跑一次：

```bash
python release_gate.py                    # 完整门禁：C1–C6
python release_gate.py --no-regression   # 跳过全量回归（快速静态核验）
python release_gate.py --self-test       # 门禁自检：构造被破坏的副本，验证能拦下
```

| 检查 | 内容 |
|---|---|
| C1 版本一致性 | 以 `server.py: APP_VERSION` 为唯一真值，核对界面按钮、两个 bat、README 标题、CHANGELOG 首段 |
| C2 门禁矩阵在册 | G1–G6 六条断言在位，且 `tests/` 下每个测试组都已在 `run_tests.py` 注册 |
| C3 静态安全面 | CLI 零删除 API、调度模块零删除调用、引导模块零执行面 |
| C4 文档同步 | 版本路线、功能编号连续、无写死的过期组数、PLAN/文件清单齐全 |
| C5 双形态产物 | 源码形态与 onefile exe 形态的 `--version` 一致且零删除 |
| C6 全量回归 | 调用 `run_tests.py`，退出码必须为 0 |

任一 FAIL 即退出码 `1` 并禁止发版；通过时报告写入 `logs/gate_report.json` 留痕。门禁脚本自身零删除面（AST 级核验），只读取文件并调用既有测试/冒烟脚本。

## 常见问题

- **「拒绝访问 / 权限不够」**：两种情况——
  1. 普通权限运行，目标目录的 ACL 不允许删除 → 关掉黑窗口，改双击 `以管理员身份启动.bat`，UAC 选「是」
  2. 该目录被**保护规则**拦截（红色「系统/程序」），这类是**故意不让删**的，删了会坏软件
- **`MicrosoftEdge` 现在能删了？** 能。1.0 的误伤已修：`Local\MicrosoftEdge` 是独立目录，不属于 `Local\Microsoft`。
- **「文件正被占用」**：先关闭对应软件（浏览器、微信、游戏客户端等）再重试
- **回收站方式后可用空间没变**：正常。移入回收站不释放空间，用侧栏「清空回收站」（需输入确认词）后才真正释放
- **移动模式**：先搬到 `D:\AppDataBackup` 观察一两周；搬错了在结果页点「撤销本次移动」即可整体搬回
- **扫描慢**：全量约 **6-7 秒**（70 GB / 56 万文件，默认 4 个并行 worker；本机实测中位数 6.55s，未达到规划里 ≤6s 的目标，原因是数据增长与系统负载，详见 `PLAN-1.4` 偏差 #9）；之后增量通常 <1 秒。想改并行度或退回单线程，启动前设环境变量 `APP_SCAN_WORKERS`（1-16，`=1` 为串行回退）
- **展开后子目录显示「—」**：该目录统计超时（1.5 秒预算），已跳过，不影响其他项
- **只读属性文件**：工具会自动清掉只读属性后再删，不需要手动 `attrib -R`
- **定时自动清理没执行？** 看设置页状态行的「当前判定」：默认关闭、扫描结果超 7 天、未到计划时刻、本周期已跑过都会跳过；另外服务必须保持运行（关掉黑窗口即停止）。v1.5 起，执行失败（无 safe 项、权限不足等）与调度异常都会显示在状态行并写进历史页，不再无声无息
- **「变化」页签全是 0？** 对比的是两次扫描之间**扫描树里可见目录**的增减；没改动或刚清理完本来就是 0。若页面提示「本次为增量扫描」，说明被复用的子树按无变化计、增长/缩小可能低估，点「强制全量重扫」取精确值
- **「扩展名」页签类型特别少 / 总量偏小？** 说明当前是增量轮次且旧快照里还没有扩展名数据，只统计到了实扫文件（页面会明确提示）。点右上「强制全量重扫」一次即可刷新；全量轮次会显示「本次为全量扫描」
- **为什么「扩展名」页签不能直接清理？** 全树里混着 `.exe`、`.dll`、数据库等运行必需文件，按类型一键删风险太高。本页只做只读分析；按类型清理请到「大文件 → 按扩展名聚合」，那里只列出可清理项并走完整确认流程
- **不想看空间预警？** 设置页把「空间预警阈值 GB」填 `0` 即关闭；调高阈值也可让它只在更极端的占用下出现。横幅本身不会执行任何删除
- **命令行只想预览、不想真删？** 用 `--dry-run`，或 `--oneclick` 但不加 `--yes`（退出码 `4`）——两条路径都保证文件系统零变化。只有 `--oneclick --yes` 才会执行，且仍只清绿色「安全缓存」并移入回收站

## 清理建议（优先级从高到低）

1. **安全缓存**（绿色）：`Local\Temp`、`NVIDIA\DXCache`、`AMD\DxCache`、`D3DSCache`、`CrashDumps`、`pip\cache`
2. 各软件的 `Cache` / `Code Cache` / `GPUCache`（黄色，逐个看说明）
3. 浏览器/IM 的旧版本残留
4. 大文件页签里的 `.dmp`、`.log`、`.old`
5. **不要动**：Docker 的 `wsl\disk\docker_data.vhdx`（删了容器数据全没）、`Tencent\WXWork`（企微聊天记录）、`Doubao` 等正在使用的应用数据
