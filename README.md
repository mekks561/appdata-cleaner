# AppData 磁盘清理助手 v1.3.0

查看并清理 `C:\Users\<你>\AppData` 下越积越大的目录。纯 Python 标准库实现，**无需安装任何依赖**，不需要 Node、不需要联网。

## 环境要求

| 项 | 要求 |
|---|---|
| Python | **3.9 或更高**（低于 3.9 会直接提示退出） |
| 系统 | Windows 10 / 11（依赖系统回收站 Shell API） |
| 依赖 | 无。`pip install` 一步都不需要 |

## 使用

两个启动入口，内容都是纯 ASCII，任何系统语言下都不会乱码：

| 文件 | 用途 |
|---|---|
| `启动工具.bat` | 普通权限，日常清理缓存够用 |
| `以管理员身份启动.bat` | 会弹 UAC，点「是」后以管理员运行。遇到「拒绝访问」时用这个 |

浏览器会自动打开 `http://127.0.0.1:8765`。

1. 点「开始扫描」——第二次扫描走**增量**，通常不到 1 秒（需要精确值点「强制全量重扫」）
2. 用顶部**搜索框**（支持 `*` 通配，`/` 聚焦、`Esc` 清空）和**筛选 chips** 缩小范围
3. 勾选要清理的项目（红色「系统/程序」项禁选，`↑↓` + `空格` 也能选）
4. 点「预览并清理」→ 逐项核对体积、级别与用途说明 → 选处理方式 → 勾选两项确认 → 执行
5. 「移动到指定文件夹」执行后可**一键撤销**；结果页/历史页都能撤
6. 想省事就用侧栏的**一键清理安全缓存**：清单由服务端从扫描树枚举，只含绿色「安全缓存」项，疑似/数据/系统目录绝不参与，执行前进回收站、可还原
7. 「设置」页签可改默认移动目标、端口，并添加**自定义规则**（格式 `路径段/段 | 级别 | 说明`）——用户 protected 优先级最高，但 safe 永远改不动系统保护目录

## 四级分类

| 级别 | 含义 | 可否删除 |
|---|---|---|
| 安全缓存（绿） | 命中已知规则：系统临时文件、着色器缓存、崩溃转储、包管理器缓存。删了由程序重建 | 可删 |
| 疑似缓存（黄） | 名字像缓存但不在已知清单内，或厂商根目录（如 `Local\NVIDIA`） | 可删，但请先看说明 |
| 用户数据（蓝） | 程序配置、聊天记录、模型文件等 | 可删，风险自负 |
| 系统/程序（红） | `Local\Microsoft`、`Local\Programs`、`Local\Packages` 等 | **禁止删除**，仅可查看 |

鼠标悬停在级别标签上，会显示该目录「删了会怎样」。

## 安全设计

| 机制 | 说明 |
|---|---|
| 默认回收站 | 删除走系统回收站（可还原），永久删除需额外输入「永久删除」四字 |
| 段级保护规则 | 按路径段精确匹配，`Local\Microsoft` 拦截，但 `Local\MicrosoftEdge` 不会被误伤 |
| 二次确认令牌 | 预览生成一次性令牌（`secrets` 生成，10 分钟有效），执行时校验清单未被中途修改，用后即废 |
| 小批量逐项校验 | 每批最多 10 项，逐项校验是否真的删除成功 |
| 越界拒绝 | 只允许操作扫描根目录内部的路径，`C:\Windows` 等直接拒绝 |
| 目标目录校验 | 移动目标不能是系统目录、盘符根，也不能在被扫描目录内部 |
| 请求来源校验 | 校验 `Origin`/`Referer` 与 `Host`，挡住跨站请求 |
| 撤销清单校验 | manifestId 只接受严格格式，杜绝 `../` 穿越；逐项独立成败 |
| 操作日志 | `logs/clean-YYYYMMDD.log`（人类可读）+ `logs/clean-YYYYMMDD.jsonl`（历史页数据源） |

## 增量扫描的边界（重要）

增量只复用**最深一层**且「目录 mtime 未变、近 10 分钟无任何写入」的子树；上层目录每次都实际枚举，所以**目录结构永远准确**。唯一已知的近似场景：文件在目录内被**原地改写**（大小变化但目录 mtime 不变），此时体积沿用旧值。界面上出现蓝色「增量扫描」提示条时即为该状态，点「强制全量重扫」可取精确值。

## 测试

```bash
python run_tests.py
```

会自动拉起服务并依次跑五组：

- `tests/test_rules.py` —— 规则层 47 项（含 1.0 两处误判的回归用例）
- `tests/test_api.py` —— 接口与安全 30 项（跨站、越界、令牌重放、目标目录、截断字段）
- `tests/test_flow.py` —— 端到端 20 项（扫描→回收站→移动→撤销→永久删除→只读文件→保护目录）
- `tests/test_increment.py` —— 增量 14 项（冷目录复用、深层新增检出、快照落盘、fresh 强制全量）
- `tests/test_m3.py` —— 历史与撤销 21 项（manifest、路径穿越拒绝、undo 回滚、清空回收站守门）

退出码 0 表示全绿。测试会重建 `testdata/`，跑完即可删。

## 常见问题

- **「拒绝访问 / 权限不够」**：两种情况——
  1. 普通权限运行，目标目录的 ACL 不允许删除 → 关掉黑窗口，改双击 `以管理员身份启动.bat`，UAC 选「是」
  2. 该目录被**保护规则**拦截（红色「系统/程序」），这类是**故意不让删**的，删了会坏软件
- **`MicrosoftEdge` 现在能删了？** 能。1.0 的误伤已修：`Local\MicrosoftEdge` 是独立目录，不属于 `Local\Microsoft`。
- **「文件正被占用」**：先关闭对应软件（浏览器、微信、游戏客户端等）再重试
- **回收站方式后可用空间没变**：正常。移入回收站不释放空间，用侧栏「清空回收站」（需输入确认词）后才真正释放
- **移动模式**：先搬到 `D:\AppDataBackup` 观察一两周；搬错了在结果页点「撤销本次移动」即可整体搬回
- **扫描慢**：首次全量约 10-15 秒（57 万文件）；之后增量通常 <1 秒
- **展开后子目录显示「—」**：该目录统计超时（1.5 秒预算），已跳过，不影响其他项
- **只读属性文件**：工具会自动清掉只读属性后再删，不需要手动 `attrib -R`

## 清理建议（优先级从高到低）

1. **安全缓存**（绿色）：`Local\Temp`、`NVIDIA\DXCache`、`AMD\DxCache`、`D3DSCache`、`CrashDumps`、`pip\cache`
2. 各软件的 `Cache` / `Code Cache` / `GPUCache`（黄色，逐个看说明）
3. 浏览器/IM 的旧版本残留
4. 大文件页签里的 `.dmp`、`.log`、`.old`
5. **不要动**：Docker 的 `wsl\disk\docker_data.vhdx`（删了容器数据全没）、`Tencent\WXWork`（企微聊天记录）、`Doubao` 等正在使用的应用数据
