# AppData 磁盘清理助手 v1.5.0

查看并清理 `C:\Users\<你>\AppData` 下越积越大的目录。纯 Python 标准库实现，**无需安装任何依赖**，不需要 Node、不需要联网。

> 版本路线：次版本依次递增、不跳号 —— 1.6 CLI → 1.7 规则库导入导出 → 1.8「申请解锁」引导 → 1.9 多根目录 → **2.0.0 稳定收口版**。详见 `PLAN-1.5.md`；1.6 规划见 `PLAN-1.6.md`。

## 环境要求

| 项 | 要求 |
|---|---|
| Python | **3.9 或更高**（低于 3.9 会直接提示退出） |
| 系统 | Windows 10 / 11（依赖系统回收站 Shell API） |
| 依赖 | 无。`pip install` 一步都不需要 |

## 使用

两个启动入口，内容都是纯 ASCII，任何系统语言下都不会乱码：

| 文件 | 用途 |
|---|---|
| `启动工具.bat` | 普通权限，日常清理缓存够用 |
| `以管理员身份启动.bat` | 会弹 UAC，点「是」后以管理员运行。遇到「拒绝访问」时用这个 |

也可以打包成**单文件 exe**（无需安装 Python 的机器也能跑）：

```
build_exe.bat        （或命令行：python -m PyInstaller --onefile --name AppDataCleaner --add-data "static;static" server.py）
```

产物 `dist\AppDataCleaner.exe` 约 9.5 MB，双击即用；`config.json`/`logs`/`cache` 自动生成在 exe 旁边。exe 不内嵌 UAC 清单（避免每次启动弹窗），提权走界面里的「以管理员身份重启」。

浏览器会自动打开 `http://127.0.0.1:8765`。服务启动后会**自动在后台预热扫描**，打开页面即有数据。

1. 点「开始扫描」——第二次扫描走**增量**，通常不到 1 秒（需要精确值点「强制全量重扫」）
2. 用顶部**搜索框**（支持 `*` 通配，`/` 聚焦、`Esc` 清空）和**筛选 chips** 缩小范围
3. 勾选要清理的项目（红色「系统/程序」项禁选，`↑↓` + `空格` 也能选）
4. 点「预览并清理」→ 逐项核对体积、级别与用途说明 → 选处理方式 → 勾选两项确认 → 执行
5. 「移动到指定文件夹」执行后可**一键撤销**；结果页/历史页都能撤
6. 想省事就用侧栏的**一键清理安全缓存**：清单由服务端从扫描树枚举，只含绿色「安全缓存」项，疑似/数据/系统目录绝不参与，执行前进回收站、可还原
7. 「重复文件」页签：按**内容 MD5 全等**找重复（0 误报），每组默认保留最新一份、其余进回收站；硬链接/云盘占位/系统保护目录自动跳过；哈希有 30s 预算，超时给部分结果并标注
8. 「设置」页签可改默认移动目标、端口、重复检测参数，并添加**自定义规则**（格式 `路径段/段 | 级别 | 说明`）——用户 protected 优先级最高，但 safe 永远改不动系统保护目录
9. 普通权限遇到「拒绝访问」不用重启：顶部横幅点**「以管理员身份重启」**，UAC 点「是」后服务自动以管理员重启、页面自动恢复
10. 「历史」页签顶部有**近 30 天清理趋势图**（每天释放空间折线，峰值自动标注）；「大文件」页签可切**「按扩展名聚合」**视图，勾一个类型即选中该类型下全部可清理文件，走同一确认流执行
11. 想彻底不管就用设置页的**定时自动清理**（v1.4 新增）：默认关闭，可选每天/每周与执行时刻；开启前先点「预览将清理的内容」，状态行会披露下次计划、上次执行与释放量、失败项与失败原因（v1.5 起）与跳过原因。只清绿色「安全缓存」，与一键清理是同一份服务端清单
12. 想知道「这几天什么在偷偷涨」就看**「变化」页签**：与上次扫描对比，列出新增目录、已移除、增长 Top20、缩小 Top20 和净变化。对比的是两棵扫描结果树、不额外读盘；本次若为增量扫描会提示增长/缩小可能低估，点「强制全量重扫」取精确值。第一次扫描没有对比基准，再扫一次即可
13. **「扩展名」页签**按全树文件类型汇总占用、文件数与占比条，点一行展开该类型主要藏在哪些目录。统计覆盖本次扫描读到的**全部文件**（不只是大文件），**本页只读**；要按类型清理请回「大文件 → 按扩展名聚合」，走同一套预览确认流
14. AppData 总量超过**空间预警阈值**（设置页，默认 10 GB、填 0 关闭）时，结果页顶部出横幅并给出超出量与两个入口（一键清理安全缓存 / 去查重复文件）。**只是提醒，不会自动删除任何东西**

## 四级分类

| 级别 | 含义 | 可否删除 |
|---|---|---|
| 安全缓存（绿） | 命中已知规则：系统临时文件、着色器缓存、崩溃转储、包管理器缓存。删了由程序重建 | 可删 |
| 疑似缓存（黄） | 名字像缓存但不在已知清单内，或厂商根目录（如 `Local\NVIDIA`） | 可删，但请先看说明 |
| 用户数据（蓝） | 程序配置、聊天记录、模型文件等 | 可删，风险自负 |
| 系统/程序（红） | `Local\Microsoft`、`Local\Programs`、`Local\Packages` 等 | **禁止删除**，仅可查看 |

鼠标悬停在级别标签上，会显示该目录「删了会怎样」。

## 安全设计

| 机制 | 说明 |
|---|---|
| 默认回收站 | 删除走系统回收站（可还原），永久删除需额外输入「永久删除」四字 |
| 段级保护规则 | 按路径段精确匹配，`Local\Microsoft` 拦截，但 `Local\MicrosoftEdge` 不会被误伤 |
| 二次确认令牌 | 预览生成一次性令牌（`secrets` 生成，10 分钟有效），执行时校验清单未被中途修改，用后即废 |
| 小批量逐项校验 | 每批最多 10 项，逐项校验是否真的删除成功 |
| 越界拒绝 | 只允许操作扫描根目录内部的路径，`C:\Windows` 等直接拒绝 |
| 目标目录校验 | 移动目标不能是系统目录、盘符根，也不能在被扫描目录内部 |
| 请求来源校验 | 校验 `Origin`/`Referer` 与 `Host`，挡住跨站请求 |
| 撤销清单校验 | manifestId 只接受严格格式，杜绝 `../` 穿越；逐项独立成败 |
| 操作日志 | `logs/clean-YYYYMMDD.log`（人类可读）+ `logs/clean-YYYYMMDD.jsonl`（历史页数据源） |
| 定时自动清理四条红线 | 默认关闭 · 只清 `safe` 级 · 扫描结果超 7 天跳过本轮 · 只进回收站且写历史（`auto-oneclick`）；与一键清理共用同一份服务端枚举清单，自动清理不可能清得更多 |

## 增量扫描的边界（重要）

增量只复用**最深一层**且「目录 mtime 未变、近 10 分钟无任何写入」的子树；上层目录每次都实际枚举，所以**目录结构永远准确**。唯一已知的近似场景：文件在目录内被**原地改写**（大小变化但目录 mtime 不变），此时体积沿用旧值。界面上出现蓝色「增量扫描」提示条时即为该状态，点「强制全量重扫」可取精确值。

另外 Windows 的目录枚举缓存可能让「刚新增的文件」在极短时间内不体现在父目录枚举出的 mtime 上，工具已在最深一层用直接路径复核一次 mtime；若仍怀疑数值不准，用「强制全量重扫」兜底。

**「变化」与「扩展名」两个分析页同样受增量影响**：复用子树沿用上次统计并标「可能低估」。若旧快照里还没有扩展名数据（刚升级到 1.4 时），首轮增量只统计到实扫文件、低估会更明显，页面会用更醒目的提示要求点一次「强制全量重扫」；全量扫描的聚合总量与文件数则与扫描树严格相等。

## 常见问题

- **「拒绝访问 / 权限不够」**：两种情况——
  1. 普通权限运行，目标目录的 ACL 不允许删除 → 关掉黑窗口，改双击 `以管理员身份启动.bat`，UAC 选「是」
  2. 该目录被**保护规则**拦截（红色「系统/程序」），这类是**故意不让删**的，删了会坏软件
- **`MicrosoftEdge` 现在能删了？** 能。1.0 的误伤已修：`Local\MicrosoftEdge` 是独立目录，不属于 `Local\Microsoft`。
- **「文件正被占用」**：先关闭对应软件（浏览器、微信、游戏客户端等）再重试
- **回收站方式后可用空间没变**：正常。移入回收站不释放空间，用侧栏「清空回收站」（需输入确认词）后才真正释放
- **移动模式**：先搬到 `D:\AppDataBackup` 观察一两周；搬错了在结果页点「撤销本次移动」即可整体搬回
- **扫描慢**：全量约 **6-7 秒**（70 GB / 56 万文件，默认 4 个并行 worker；本机实测中位数 6.55s，未达到规划里 ≤6s 的目标，原因是数据增长与系统负载，详见 `PLAN-1.4` 偏差 #9）；之后增量通常 <1 秒。想改并行度或退回单线程，启动前设环境变量 `APP_SCAN_WORKERS`（1-16，`=1` 为串行回退）
- **展开后子目录显示「—」**：该目录统计超时（1.5 秒预算），已跳过，不影响其他项
- **只读属性文件**：工具会自动清掉只读属性后再删，不需要手动 `attrib -R`
- **定时自动清理没执行？** 看设置页状态行的「当前判定」：默认关闭、扫描结果超 7 天、未到计划时刻、本周期已跑过都会跳过；另外服务必须保持运行（关掉黑窗口即停止）。v1.5 起，执行失败（无 safe 项、权限不足等）与调度异常都会显示在状态行并写进历史页，不再无声无息
- **「变化」页签全是 0？** 对比的是两次扫描之间**扫描树里可见目录**的增减；没改动或刚清理完本来就是 0。若页面提示「本次为增量扫描」，说明被复用的子树按无变化计、增长/缩小可能低估，点「强制全量重扫」取精确值
- **「扩展名」页签类型特别少 / 总量偏小？** 说明当前是增量轮次且旧快照里还没有扩展名数据，只统计到了实扫文件（页面会明确提示）。点右上「强制全量重扫」一次即可刷新；全量轮次会显示「本次为全量扫描」
- **为什么「扩展名」页签不能直接清理？** 全树里混着 `.exe`、`.dll`、数据库等运行必需文件，按类型一键删风险太高。本页只做只读分析；按类型清理请到「大文件 → 按扩展名聚合」，那里只列出可清理项并走完整确认流程
- **不想看空间预警？** 设置页把「空间预警阈值 GB」填 `0` 即关闭；调高阈值也可让它只在更极端的占用下出现。横幅本身不会执行任何删除

## 清理建议（优先级从高到低）

1. **安全缓存**（绿色）：`Local\Temp`、`NVIDIA\DXCache`、`AMD\DxCache`、`D3DSCache`、`CrashDumps`、`pip\cache`
2. 各软件的 `Cache` / `Code Cache` / `GPUCache`（黄色，逐个看说明）
3. 浏览器/IM 的旧版本残留
4. 大文件页签里的 `.dmp`、`.log`、`.old`
5. **不要动**：Docker 的 `wsl\disk\docker_data.vhdx`（删了容器数据全没）、`Tencent\WXWork`（企微聊天记录）、`Doubao` 等正在使用的应用数据
